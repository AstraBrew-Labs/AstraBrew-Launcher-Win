## 窗口规范落地（禁最大化 / DPI / 多屏 / 断屏回迁）

- 新增 `Services/WindowPlacement.cs`：窗口规范的唯一实现点，`MainWindow.SetupWindow` 里 new 出来，
  窗口 `Closed` 时 Dispose。
  - 禁最大化：`OverlappedPresenter.IsMaximizable = false` + 子类化拦截 `WM_SYSCOMMAND/SC_MAXIMIZE`
    + `AppWindow.Changed` 里检测 `Maximized` 兜底 `Restore()`。
  - DPI：尺寸以 DIP 常量描述（1180×780 / 最小 900×620），落像素时乘 `GetDpiForWindow/96`；
    最小尺寸在 `WM_GETMINMAXINFO` 里按当前 DPI 实时计算，不依赖 `PreferredMinimum*`
    （那组属性单位在版本间不一致，已置 null）。
  - 缩放适配：默认尺寸与最小尺寸都夹在「工作区 × 0.92」内，1366×768@150% 这类小逻辑分辨率屏不会开窗即满屏。
  - 多屏：`DisplayArea.CreateWatcher()`（注意不是 `CreateForWindowId`，该重载在 2.5.1 不存在）
    监听 Added/Removed/Updated/EnumerationCompleted，外加 `WM_DISPLAYCHANGE`、`WM_SETTINGCHANGE(SPI_SETWORKAREA)` 兜底。
  - 断屏回迁：按交集面积找宿主显示器，交集为 0 即回主屏居中；跨屏 DPI 变化导致超出工作区时 `ShrinkToWorkArea` 收回。
- 移除 `MainWindow` 里的 `DefaultWidth/DefaultHeight`、`CenterOnScreen`、`GetDpiForWindow` 与
  `PreferredMinimumWidth = 900` 旧逻辑。
- `AGENTS.md` 窗口规范下补了一行实现位置指引。

## 修复启动闪退（0xc000027b / CoreMessagingXP.dll）

- 现象：窗口规范第一版构建通过但一启动就闪退，事件日志只有
  `异常代码 0xc000027b`（STOWED_EXCEPTION）+ 出错模块 `CoreMessagingXP.dll`，无 .NET Runtime 条目。
- 判定：stowed exception 崩在 CoreMessaging = 托管异常穿透了 DispatcherQueue 消息泵，
  即异常发生在 dispatcher/事件回调里。原实现里 `DisplayAreaWatcher` 在 MainWindow 构造函数中
  `Start()`，`EnumerationCompleted` 立刻触发 `ScheduleSync → EnsureOnScreen → DisplayArea.FindAll +
  AppWindow.MoveAndResize`，而这一切发生在 `Window.Activate()` 之前。
- 修复（三条硬约束，已写进 WindowPlacement 类注释）：
  1. 窗口过程内只调 Win32，绝不调 WinRT；几何计算改用 `MonitorFromWindow/GetMonitorInfo/EnumDisplayMonitors`。
  2. 删掉 `DisplayAreaWatcher`，拓扑变化改用 `WM_DISPLAYCHANGE` / `WM_SETTINGCHANGE(SPI_SETWORKAREA)` / `WM_DPICHANGED`。
  3. 所有回调（WndProc、AppWindow.Changed、Dispatcher 队列）全部 try/catch，失败只降级并写
     `%Temp%/astrabrew-launcher/window.log`；`App` 里加了 `crash.log` 兜底。
- 另修两处可疑点：`SetupWindow()` 提到 `SetupTitleBar()` 之前（先设 presenter 再 ExtendsContentIntoTitleBar）；
  `PreferredMinimumWidth/Height` 不再置 null（改回 900/620，与像素级约束取较大者，两种单位解释都正确）。
- 验证：`timeout 12` 运行返回 124（存活到被杀）；后台启动后进程 Responding=True、MainWindowHandle 有效、
  持续 28s 无崩溃、无 crash.log / window.log。
- 教训：**WinUI 3 里窗口装饰类代码的任何异常都会变成静默闪退**，凡是 WndProc / 事件回调一律先加 try/catch。

## 修复「本地实例 → 内置实例」无法切回

- 根因：`VersionPage` 的 `_currentSourceIsLocal` 只有单向置 true 的路径（`LocalUse_Click`），
  内置实例页只有「切换版本」按钮（只改内置代码版本，不改使用来源），因此切到本地后无主动回退入口；
  唯一复位发生在「移除当前本地实例」的副作用里。
- 修复（`Views/VersionPage.xaml` + `.xaml.cs`）：
  - 内置卡头部右侧新增状态双胶囊 `BuiltinActivePill`（使用中，强调色）/ `BuiltinIdlePill`（已安装，成功色），
    并新增「使用内置实例」按钮 `UseBuiltinBtn`，**仅在使用本地实例时出现**，与本地行内「使用」按钮对称。
  - `UpdateHeaderCurrent()` 定为「当前来源」的唯一同步点，末尾统一调 `UpdateBuiltinActiveState()`
    （页头胶囊 + 内置卡状态 + 关于页徽章一处改、三处同步）。
  - 新增 `SwitchToBuiltin()`：清空所有本地行的 IsCurrent、复位来源、刷新列表与按钮态；
    `UseBuiltin_Click` 走它并给出反馈条。
  - 移除当前本地实例时清空 `_currentLocalVersion`，反馈条明确「已回落到内置实例」。
  - `UpdateSwitchButton()`：当前在用本地实例时把提示改为「换版只更新内置代码、不改变使用来源」，
    避免用户误以为换版等于切回内置；`FinishSwitch()` 在本地生效时同样提示去点「使用内置实例」。
- 验证：`dotnet build -p:Platform=x64` 0 警告 0 错误（注意该工程必须显式传 Platform，否则报
  `WindowsAppSDKSelfContained requires a supported Windows architecture`）。

## 修复仪表盘 ↔ 版本管理页实例状态不同步（改为单一数据源）

- 根因：两页各存一份实例状态。仪表盘用页面内的 `TavernVersion[] Versions` 静态数组（还自带一套
  与版本页不同的假路径 `D:\Tavern\1.19.x`），版本管理页用 `_localData` + `_builtinVersion` +
  `_currentSourceIsLocal`，两者之间没有任何事件通道；`ActiveInstance` 只是版本页单向写出去的只读镜像。
- 重构：新增 `Services/TavernInstances.cs` 作为**全应用唯一的实例清单与当前选择**，
  删除 `Services/ActiveInstance.cs`（其 `TavernInstanceKind` 枚举一并迁入新文件）。
  - `TavernInstance`（Kind/Version/Path/Node/Size/DepsReady + `KernelLabel`/`DisplayName`/`DisplayLabel`）
    由 `TavernInstances` 独占构造（ctor 为 internal），页面只拿共享引用，杜绝「各自 new 一份」。
  - `TavernInstances`：`All`（内置恒在索引 0）/ `Locals` / `Current` / `IsBuiltinActive`，
    动作 `Use` / `SetBuiltinVersion` / `SetDepsReady` / `RemoveLocal`，全部幂等并统一抛 `Changed`。
    `StableReleases` 版本表也上移到这里，版本页与仪表盘不再各抄一份。
- 页面改造（动作只改状态，界面统一由 `Changed` 重画）：
  - `VersionPage`：去掉 `_localData`/`_builtinVersion`/`_currentSourceIsLocal`/`_currentLocalVersion`，
    `OnLoaded` 订阅、`OnUnloaded` 退订（先减后加防重复），`SyncFromCatalog()` 统一重画；
    行对象 `LocalInstanceRow` 增加 `Instance` 引用，交互不再按版本号反查。
    另修一处：通道单选项（稳定版/开发版）现跟随内置实例实际版本回填，否则换到开发版后
    离开再回本页会显示「稳定版」而代码是 staging。
  - `DashboardPage`：删掉 `TavernVersion`/`Versions` 与 XAML 里写死的 4 个 `ComboBoxItem`，
    下拉项由 `TavernInstances.All` 生成（`Tag` 挂实例对象），`_versionSignature` 指纹决定是否重建；
    `_syncingVersion` 屏蔽程序回填，选中即 `Use`；选到缺依赖的本地实例会弹回并给 Warning 提示。
- 冒烟：`timeout 12` 启动 exe 返回 124（存活至被杀），无 crash.log，构造期填充下拉框无异常。
- 遗留：`ExtensionsPage` / `ResourcesPage` 的「目标实例 · 内置 v1.19.2」胶囊仍是写死文案，
  且同屏的路径也是写死的内置目录；只改胶囊会与路径自相矛盾，需连同路径一起按实例推导，本次未动。
- `AGENTS.md` 增加「实例状态」一节，明确唯一来源与「不要在页面里另存一份」。
