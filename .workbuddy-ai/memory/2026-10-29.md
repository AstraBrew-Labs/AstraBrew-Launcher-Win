# 2026-10-29

## 窗口规范落地（禁最大化 / DPI / 多屏 / 断屏回迁）

- 新增 `Services/WindowPlacement.cs`：窗口规范的唯一实现点，`MainWindow.SetupWindow` 里 new 出来，
  窗口 `Closed` 时 Dispose。
  - 禁最大化：`OverlappedPresenter.IsMaximizable = false` + 子类化拦截 `WM_SYSCOMMAND/SC_MAXIMIZE`
    + `AppWindow.Changed` 里检测 `Maximized` 兜底 `Restore()`。
  - DPI：尺寸以 DIP 常量描述（1180×780 / 最小 900×620），落像素时乘 `GetDpiForWindow/96`；
    最小尺寸在 `WM_GETMINMAXINFO` 里按当前 DPI 实时计算，不依赖 `PreferredMinimum*`
    （那组属性单位在版本间不一致，已置 null）。
  - 缩放适配：默认尺寸与最小尺寸都夹在「工作区 × 0.92」内，1366×768@150% 这类小逻辑分辨率屏不会开窗即满屏。
  - 多屏：`DisplayArea.CreateWatcher()`（注意不是 `CreateForWindowId`，该重载在 2.5.1 不存在）
    监听 Added/Removed/Updated/EnumerationCompleted，外加 `WM_DISPLAYCHANGE`、`WM_SETTINGCHANGE(SPI_SETWORKAREA)` 兜底。
  - 断屏回迁：按交集面积找宿主显示器，交集为 0 即回主屏居中；跨屏 DPI 变化导致超出工作区时 `ShrinkToWorkArea` 收回。
- 移除 `MainWindow` 里的 `DefaultWidth/DefaultHeight`、`CenterOnScreen`、`GetDpiForWindow` 与
  `PreferredMinimumWidth = 900` 旧逻辑。
- `AGENTS.md` 窗口规范下补了一行实现位置指引。

## 修复启动闪退（0xc000027b / CoreMessagingXP.dll）

- 现象：窗口规范第一版构建通过但一启动就闪退，事件日志只有
  `异常代码 0xc000027b`（STOWED_EXCEPTION）+ 出错模块 `CoreMessagingXP.dll`，无 .NET Runtime 条目。
- 判定：stowed exception 崩在 CoreMessaging = 托管异常穿透了 DispatcherQueue 消息泵，
  即异常发生在 dispatcher/事件回调里。原实现里 `DisplayAreaWatcher` 在 MainWindow 构造函数中
  `Start()`，`EnumerationCompleted` 立刻触发 `ScheduleSync → EnsureOnScreen → DisplayArea.FindAll +
  AppWindow.MoveAndResize`，而这一切发生在 `Window.Activate()` 之前。
- 修复（三条硬约束，已写进 WindowPlacement 类注释）：
  1. 窗口过程内只调 Win32，绝不调 WinRT；几何计算改用 `MonitorFromWindow/GetMonitorInfo/EnumDisplayMonitors`。
  2. 删掉 `DisplayAreaWatcher`，拓扑变化改用 `WM_DISPLAYCHANGE` / `WM_SETTINGCHANGE(SPI_SETWORKAREA)` / `WM_DPICHANGED`。
  3. 所有回调（WndProc、AppWindow.Changed、Dispatcher 队列）全部 try/catch，失败只降级并写
     `%Temp%/astrabrew-launcher/window.log`；`App` 里加了 `crash.log` 兜底。
- 另修两处可疑点：`SetupWindow()` 提到 `SetupTitleBar()` 之前（先设 presenter 再 ExtendsContentIntoTitleBar）；
  `PreferredMinimumWidth/Height` 不再置 null（改回 900/620，与像素级约束取较大者，两种单位解释都正确）。
- 验证：`timeout 12` 运行返回 124（存活到被杀）；后台启动后进程 Responding=True、MainWindowHandle 有效、
  持续 28s 无崩溃、无 crash.log / window.log。
- 教训：**WinUI 3 里窗口装饰类代码的任何异常都会变成静默闪退**，凡是 WndProc / 事件回调一律先加 try/catch。
